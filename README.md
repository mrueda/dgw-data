# DGW data and tools

Resource packaging for [Digital Genome Workstation](https://github.com/mrueda/digital-genome-workstation).

Author: Manuel Rueda. This repository is being prepared; no resource release is published yet.

## Tool builds

The manually triggered **Build DGW tools** GitHub Actions workflow builds bcftools,
bgzip and tabix on Linux ARM64/x86-64, macOS ARM64/Intel and Windows x86-64.
It produces private workflow artifacts, not public releases. Nothing runs on push.
GitHub-hosted builds in a private repository consume the account's Actions allowance.

Sources are pinned by version and SHA-256 in `sources.json`. BCFtools's official
release archive includes HTSlib; do not substitute GitHub's autogenerated source archive.

Each build statically links zlib and rejects unexpected runtime dependencies.
Only operating-system libraries should remain. Windows users should not need MSYS2
or WSL. Packages are experimental until their native CI job and clean-machine tests pass.
The Linux x86-64 baseline is Ubuntu 22.04; ARM64 is Ubuntu 24.04. macOS targets 13+.
This is not a promise of compatibility with older OS releases.

The initial minimal build covers DGW's local VCF/BCF operations. It disables plugins,
HTSlib network access, libdeflate, and bz2/lzma CRAM support. Downloads are handled by
DGW, not these tools. It is not a general-purpose replacement for a full bcftools
installation. Benchmark before replacing the development toolchain: excluding
libdeflate may affect compression/query performance.

Tests cover strict PASS filtering, multiallelic splitting, indel normalization,
REF mismatch rejection, BGZF, tabix queries and independently evaluated missense,
stop-gained and frameshift consequences. They run on a relocated package using
paths containing spaces and non-ASCII characters. Test data is synthetic.
This is a targeted DGW smoke suite, not the complete upstream bcftools test suite.

For a local native build (Python 3.11+ with tarfile extraction filters, CMake,
Make, C compiler, Bash):

```sh
bash scripts/build.sh linux-aarch64
```

Use a fresh `work/` directory for each build. Sources and outputs stay there;
`dist/` contains archives and SHA-256 files. Build scripts do not install system tools.
Artifacts contain licenses, exact source identities, runtime audits and test results.
Archive bytes are not claimed to be reproducible across builds.

## Genome resources

Planned: separate assembly data archives, shared by all operating systems and
architectures. No genomes or external databases are committed to Git. dbNSFP is
not used. COSMIC remains user-supplied. Review redistribution terms and attribution
before uploading reference, Ensembl or ClinVar data.

## Release checklist

1. Inspect all native build results and diagnostics.
2. Test archives on clean machines without compiler environments, including DLL
   availability, code signing/security prompts and scientific result parity.
3. Benchmark against the current DGW toolchain.
4. Publish reviewed artifacts as release attachments, then update DGW's catalog.

These artifacts are not yet connected to DGW's resource installer. Its current
catalog format still needs separate data/tool composition and safe archive extraction.

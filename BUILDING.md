# Building DGW resource packages

## Platform tools

The manually triggered **Build DGW tools** GitHub Actions workflow builds
`bcftools`, `bgzip` and `tabix` on Linux ARM64/x86-64, macOS ARM64/Intel and Windows
x86-64. It creates private workflow artifacts; it never publishes a release.

Sources are pinned by version and SHA-256 in `sources.json`. The official bcftools
release archive includes HTSlib and must not be replaced with GitHub's autogenerated
source archive. The packages statically link zlib and libdeflate and reject
unexpected runtime dependencies. Windows users should not need MSYS2 or WSL.

This deliberately small build covers DGW's local VCF/BCF operations. It disables
plugins, HTSlib network access, and bz2/lzma CRAM support. DGW handles downloads. It
is not intended to replace a full bcftools installation.

Requirements for a local native build include Python 3.11 or newer with tarfile
extraction filters, CMake, Make, a C compiler, and Bash:

```sh
bash scripts/build.sh linux-aarch64
```

Use a fresh `work/` directory for each build. Sources and outputs stay there;
`dist/` contains archives and SHA-256 files. The scripts do not install system
tools. Archives include exact source identities, licenses, runtime audits and test
results. Archive bytes are not claimed to be reproducible across builds.

## Assembly data

Assembly packages are shared by all platforms. `data-packages.json` pins the size,
SHA-256 and provenance of every input so that changed local data cannot silently
enter a release.

The initial package contains:

- reference FASTA plus `.fai` and `.gzi` indexes;
- a pinned ClinVar VCF plus tabix index;
- Ensembl GTF plus DGW's SQLite gene index;
- the Ensembl GFF3 used by `bcftools csq`.

It excludes COSMIC and dbNSFP. COSMIC remains user supplied.

Build and verify an archive from an existing DGW descriptor:

```sh
python3 scripts/package_data.py build \
  --bundle /path/to/dgw-bundle.json \
  --output /path/to/release-staging

python3 scripts/package_data.py verify \
  /path/to/release-staging/dgw-data-b37-r1.tar.gz
```

The builder rejects missing provenance, input checksum changes, links and existing
output archives. Verification streams and hashes every archived file without
extracting it.

The development layout keeps working data outside this Git repository:

```text
Project_DGW/dgw-data/          # source repository
Databases/dgw/releases/        # immutable archives and checksums
Databases/dgw/installed/       # clean installation tests
```

Package creation does not grant redistribution rights. Review source terms and
attribution before publishing an archive.
